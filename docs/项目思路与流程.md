# EmotionBot 项目思路与实现流程

## 一、一句话思路

大多数人机交互只听"说了什么"，我们的机器人头多听一层"怎么说的"：把**字面**和**语气**分开判断，当两者冲突时，跟语气走，并把这种冲突变成一个看得见的表情和一句顺着语气的回应。

情绪不是分类题的终点，而是决策的起点。

---

## 二、4 条设计原则

| 原则 | 含义 | 落地方式 |
|---|---|---|
| **感知与决策解耦** | 换模型不影响策略，换策略不影响模型 | 每路模型输出统一的 7 类概率 + 置信度，融合层只认这个接口 |
| **每层都能降级** | 现场任何一环坏了，demo 都要能演 | 摄像头→纯音频；T5→笔记本麦克风；在线 TTS→本地 TTS；真机头→2D 脸 |
| **不确定就不反应** | 宁可中性，不要瞎共情 | 融合置信度 < 0.4 直接中性；单模态置信度不足不参与矛盾判断 |
| **决策可解释** | 评委要能看懂"它为什么这么判断" | 仪表盘展示每路概率、融合结果、矛盾原因、端到端延迟 |

## 四、具体流程

### 1. 输入

- **音频**：统一转成 16kHz、单声道、float32。三个来源实现同一接口：
  - `MicSource`：笔记本麦克风（sounddevice）
  - `UdpPcmSource`：T5 板推 UDP 8770，16k / s16le / 20–40ms 一包
  - `FileSource`：wav 回放，用于离线回归和录音测试
- **视频**：USB 摄像头后台线程抓帧，不阻塞音频链路。

### 2. VAD 切句

- 10ms 一帧，能量 + 过零率判断语音/静音
- 连续 500ms 静音 → 认为一句结束，尾部只保留 100ms 避免吞字
- 最短 0.4 秒、最长 15 秒；超长强制切断，防止注意力长度和显存爆炸
- 回声门控静音期间直接丢弃输入，并在门控切换时重置 VAD（避免把 TTS 尾音切成句子）

### 3. 四路感知（并行）

| 模态 | 模型/方法 | 输出 | 关键细节 |
|---|---|---|---|
| 语音识别 + 硬情感 | SenseVoiceSmall | 文本 + 7 类概率 | 一次推理同时出两样；**必须 `ban_emo_unk=True`**；硬标签平滑成 0.7 / 0.3 |
| 语音情感 | emotion2vec+ large | 7 类概率 | 模型原生 9 类，映射到 7 类后归一化 |
| 文本情感 | DashScope LLM（主）/ 关键词（备） | 7 类概率 | **只看字面**，不推断反讽——反讽留给融合层判断 |
| 人脸情绪 | MediaPipe 检测 + EmotiEffNet-B0 | 7 类概率或 None | 8fps；没有人脸返回 None，融合时当作缺失模态 |

四路都输出同一种结构：`7 类概率 + confidence（最大类概率）`。这是解耦的关键。

### 4. 融合与矛盾检测（核心）

**加权对数概率融合**：

```
w_i = confidence_i
L = Σ w_i · log P_i
P = softmax(L)
```

缺失模态的权重直接置 0 后重新归一化；每缺一路，最终置信度乘 0.9 衰减——缺得越多，越不确定。

**矛盾判定**（同时满足才成立）：

1. 文本效价 `v_text` 与语音效价 `v_speech` 符号相反
2. 两边绝对效价都 ≥ 0.35（有一边接近中性不算矛盾）
3. 两边置信度都 ≥ 0.55
4. 不能是两边都判中性

**矛盾时怎么融合**：不做平均，而是 `0.2 × 文本 + 0.8 × 语音`——跟语气走。

原因来自离线实验：文本情感存在 **semantic dominance**（语义主导）偏差，反讽句里字面的权重过强；而语气更接近说话人的真实状态。

### 5. 情绪状态平滑

单句结果直接驱动表情会抖。用 EMA 平滑：

```
ema = α · p + (1 - α) · ema       α 默认 0.35
```

- **高置信事件**（最大概率 ≥ 0.6）时 α 提到 0.75，保证反应跟得上
- **矛盾事件直接透传**，不平滑，保持 demo 的即时反应
- 标签切换有滞回（领先 0.08 且连续确认才切换），避免在两类之间反复横跳

### 6. 规则决策

融合结果 → 表情命令，规则表如下：

| 情绪 | 表情 | 强度 | 持续 |
|---|---|---|---|
| happy | happy | 0.80 | 2.5s |
| sad | sad | 0.70 | 3.0s |
| angry | angry | 0.55（收敛，不吓人） | 2.0s |
| surprise | surprised | 0.90 | 1.5s |
| fear | fear | 0.60 | 2.0s |
| disgust | disgust | 0.50 | 2.0s |
| neutral / 置信度 < 0.40 | neutral | 0 | — |
| **矛盾** | **concerned（担心）** | 0.70 | 3.0s |

`concerned` 不是模型输出的类别，是用 sad + surprised 组合出来的复合表情——专门为"口是心非"设计。

### 7. 表达

- 表情 → 22 维舵机向量 → 3 块 Pico（25Hz 下发，EMA 再平滑一层，固件本身还有限速插值）
- 空闲时叠加眨眼（3–6 秒随机）、轻微视线漂移
- 同时生成一句回应（模板或 LLM），TTS 合成并播放
- 播放前门控静音，播放中把音量包络回传给嘴部舵机（简易 viseme），播放后 + 300ms 再放开

### 8. 可视化

标准库 HTTP 服务 + 单页仪表盘，250ms 轮询：

- 三模态概率条 + 融合结果
- 矛盾横幅（显示文本标签 vs 语音标签）
- 22 维驱动的 2D 表情
- 60 秒情绪时间线、效价/唤醒轨迹
- 端到端延迟、模态缺失提示
- 手动控制：Rest / 指定表情 / 指定说话内容

## 五、一句矛盾句的完整走位

以「太好了，又要加班」（用疲惫语气）为例：

```
1. VAD 切出 2.1 秒音频
2. SenseVoice  → 文本「太好了，又要加班」，情感标签 HAPPY（0.7）
3. emotion2vec → sad 0.6 / neutral 0.25 / ...
4. 文本情感    → 字面积极 happy（置信度 0.8）
5. 融合层      → v_text > 0，v_speech < 0，两边都够确信 → conflict = True
6. 冲突重融合  → 0.2×文本 + 0.8×语音 → sad
7. 状态层      → 矛盾事件透传，不衰减
8. 策略层      → concerned 0.7 / 3.0s
9. 机器头      → sad + surprised 复合表情（担心）
10. TTS        → 顺着语气回应，而不是「恭喜你」
11. 仪表盘     → 亮起矛盾提示，显示两路标签与延迟
```

（第 2–4 步的数值是示例，用于说明链路，不代表某次实测结果。）

## 六、关键取舍与理由

| 取舍 | 选择 | 为什么 |
|---|---|---|
| 文本情感是否理解反讽 | **不理解，只看字面** | 如果让 LLM 直接判"这是反讽"，它和语音模型会给出同一个结论，矛盾就永远不会出现。把字面交给文本、语气交给语音，冲突才有信息量 |
| 矛盾时信谁 | **信语气（0.2/0.8）** | 离线实验显示文本有语义主导偏差；语气更接近真实状态 |
| 用规则还是端到端模型 | **规则策略** | 3 天工期，规则可解释、可现场调、不会突然抽风；LLM 只负责生成回复文本 |
| 仪表盘用 FastAPI 还是标准库 | **标准库 ThreadingHTTPServer** | 少一个依赖就少一个现场故障点；单机轮询足够 |
| 情绪识别准确率 | 不追求 SOTA 数字 | demo 的价值在"矛盾被看见"，不在 benchmark 涨点；模型只做可替换组件 |
| 平滑强度 | 平时 0.35，高置信 0.75 | 既要稳定不抖，又要在关键句上有明显反应 |

## 七、延迟预算与目标

| 环节 | 目标 |
|---|---|
| 一句话结束 → 融合结果 | p95 ≤ 500ms（不含 LLM） |
| 一句话结束 → 表情变化 | ≤ 0.8s |
| 人脸情绪响应 | ≤ 200ms |
| TTS 首字 | ≤ 1.5s |
| 显存常驻（四路模型） | ≈ 2.5GB，8GB 演示机留足余量 |

当前实测（开发机 3060，单句 3.5 秒音频）：ASR 约 1.15s，SER 约 0.91s，显存峰值 1.59GB。延迟偏高的部分是首次推理预热，实时链路需要单独复测。

## 八、降级路径

| 缺失的东西 | 自动/手动降级 | 影响 |
|---|---|---|
| T5 音频没通 | 笔记本麦克风 | 无 |
| 摄像头没接 | 纯音频 + 文本 | 少一路模态，置信度下降 |
| 断网 | 文本情感降级关键词；TTS 降级本地 | 识别质量下降，链路不断 |
| 机器头没装好 | `--sim` + 仪表盘 2D 脸 | 无硬件演示 |
| 模型加载失败 | `--stub` 假数据调界面 | 只演示交互与策略 |
| 显存不够 | TER 走 API、FER 降帧、SER 换 base | 延迟上升 |

## 十、怎么验证这套思路成立

| 验证项 | 方法 | 通过标准 |
|---|---|---|
| 融合正确性 | 单元测试（缺失模态、矛盾、低置信） | 概率和为 1，缺模态时置信度下降 |
| 矛盾检测有效 | 真人录 10–20 句字面/语气冲突句 | 识别率 ≥ 50%，比纯文本高 ≥ 30 点 |
| 不误伤正常句 | 开心/生气/难过各 3 句对照 | 不被误判为矛盾 |
| 实时性 | 连续说 20 句记录延迟 | 融合 p95 ≤ 500ms |
| 回声门控 | 机器人自说自话 5 分钟 | 0 次自触发 |
| 稳定性 | 连续跑 10 分钟 | 不崩、不 OOM、显存不持续上涨 |
