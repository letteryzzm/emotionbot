# 下巴和嘴部：舵机测试与表情尝试交接

> 2026-11-06。机器人头 Will Cogley Robot Head α2.0.33，这份只管**嘴部板**的 11 个舵机。
> 配图和万用表清单在 [舵机接线与上电检查.html](舵机接线与上电检查.html)。

## 现在的状态

- 嘴部舵机线已经接到板子上，**但左右和方向还没有在实物上验证过**。文档里的左右是从模型连杆方向推算的。
- 所以第一件事不是跑表情，而是一个一个确认方向和行程。
- 不要跳步：`demo_expressions.py` 和发 `R` 都会把舵机转到 rest 姿态，比如舌头 TON 会转到 130°。行程没确认前转过去可能顶死。

## 0. 准备

嘴部板的 USB 插在 ROG Linux 电脑上，你通过 Tailscale 远程登录它，不用接触其他电脑。

```bash
ssh -p 2222 collab@100.93.30.117      # 地址以项目负责人发给你的为准
git clone https://github.com/letteryzzm/emotionbot.git && cd emotionbot
uv venv --python 3.12 && uv pip install -e '.[dev]'
.venv/bin/pytest -q                   # 假硬件测试，应该全部通过
ls /dev/serial/by-id/ | grep -i micropython   # 能看到一行才说明 Pico 连上了
```

**机器人旁边必须有人守着电源。** 远程时网络一断，`X` 就发不出去。开始转舵机前先和现场的人确认，下面第 1 节的插线、拨开关也由现场的人做。

串口同一时间只能给一个程序用。这台电脑上还接着 SO-101 机械臂，不要动 `/dev/ttyACM*`，也不要动 `~/robotic/`。

嘴部板的 Pico 要已经刷好固件。没刷时先只插 USB，不接 5V：

```bash
PATH=$PWD/.venv/bin:$PATH firmware/flash.sh mouth
```

## 1. 上电顺序（每次都一样）

1. **断电插拔舵机线。** 一个舵机一竖列，棕/黑线对 − 行（靠板子边）。
2. 嘴部板 SW1 拨到**校准档**（GP28 接地，SW1 第 1、2 脚导通），舵机会全部保持 90°。
3. 确认 BOARD POWER 跳线帽插着。
4. 接 5V，再插 USB。**绝对不要接 12V。**
5. SW1 拨回运行档，舵机停在 90° 不动。

断电时先拔 USB。

校准档时 `S` 命令不起作用，发了舵机不动就先看开关。

## 2. 发命令的工具

```bash
.venv/bin/python scripts/servo_step.py
```

| 输入 | 作用 |
|---|---|
| `TON=100` | 转一个舵机 |
| `JL=85 JR=95` | 同一块板的几个舵机一起转 |
| `C` | 全部回 90° |
| `X` | **卸力，遇到异常马上发** |
| `G` | 看当前角度 |
| `q` | 退出 |

速度固定 30°/s。一步超过 15° 会被拒绝，确认没问题后在前面加 `!`，比如 `!TON=130`。

**听到持续嗡嗡响、看到零件被顶弯或舵机发热，立刻发 `X`。** 没有电脑时直接拔电源。

## 3. 确认每个舵机的位置和方向

下面的"左手边/右手边"都是**面对机器人的脸**时的方向。

| 排针 | 列 | 名字 | 舵机位置（连的零件） | 试这条 | 应该看到 |
|---|---|---|---|---|---|
| U3 | 左 | JL | 左手边 MG996R（Part_33） | `JL=85` | 下巴张开一点 |
| U3 | 右 | JR | 右手边 MG996R（JawLink） | `JR=95` | 下巴张开一点 |
| U4 | 左 | LUL | 右手边，上颌座前部（ULLLinkA） | `LUL=85` | 上唇抬起 |
| U4 | 右 | LUR | 左手边，上颌座前部（Part_35） | `LUR=95` | 上唇抬起 |
| U5 | 左 | LLL | 右手边，下颌座两侧（Part_27） | `LLL=95` | 下唇往下 |
| U5 | 右 | LLR | 左手边，下颌座两侧（Part_38） | `LLR=85` | 下唇往下 |
| U6 | 左 | CUL | 右手边，上颌座中间上面（Part_31） | `CUL=85` | 嘴角上抬 |
| U6 | 右 | CUR | 左手边，上颌座中间上面（Part_42） | `CUR=95` | 嘴角上抬 |
| U7 | 左 | CLL | 右手边，上颌座中间下面（Part_32） | `CLL=95` | 嘴角往后，略往下 |
| U7 | 右 | CLR | 左手边，上颌座中间下面（Part_43） | `CLR=85` | 嘴角往后，略往下 |
| U8 | 左 | TON | 下颌座中间（Part_20） | `TON=100` | 舌头往下 |

U8 右列 EXA 不接。

**顺序：**

1. 一次只接一个舵机：断电，插线，按第 1 节上电，试一条，再发回 `<名字>=90`。
2. **下巴要分开试。** JL 和 JR 硬连在同一个下巴上，先只接 JL 试；拔掉 JL，再只接 JR 试。两个都对了才一起接。只接一个时另一个舵机有阻力，别把角度加大。
3. 下巴两个都接上之后，**永远成对发**：`JL=85 JR=95`，两个数加起来等于 180。单独动一个会对顶，可能打坏 JawLink。
4. 其他舵机逐个加上，每接一个试一次。

**不对怎么办：**

| 现象 | 处理 |
|---|---|
| 这一对都反了 | `X`，断电，对调这一对的两个插头 |
| 只有一个反，另一半对 | 先查舵机是否放反、连杆是否接错，不要只改一边的角度 |
| 不动 | 查开关是否在运行档、插头方向、该列 + − 是否有 4.7–4.9 V |
| 90° 时位置差一点 | 拆连杆错一个齿，不要掰 |
| 几乎所有对都反 | 停下告诉项目负责人。可能要把 `head/actuators.py` 的 `ANGLE_UP_IS_CCW` 改成 `False`，再整体对调 |

下唇的方向把握最低，只来自模型推算。如果 `LLL=95` 时下唇往上，对调 U5 两个插头。

## 4. 量每个舵机的行程

方向都对了以后，从 90° 每次走 5°，走到下面的两端和 rest。**某一处顶住就停**，退回 5° 记下来。

| 舵机 | 一端 | 另一端 | rest | 实测可用范围 |
|---|---|---|---|---|
| JL | 90 闭 | 50 张 | 90 | |
| JR | 90 闭 | 130 张 | 90 | |
| LUL | 110 下 | 40 上 | 75 | |
| LUR | 70 下 | 140 上 | 105 | |
| LLL | 110 下 | 55 上 | 82 | |
| LLR | 60 下 | 110 上 | 85 | |
| CUL | 100 撇嘴 | 60 笑 | 90 | |
| CUR | 75 撇嘴 | 105 笑 | 80 | |
| CLL | 90 窄 | 120 宽 | 90 | |
| CLR | 90 窄 | 65 宽 | 90 | |
| TON | 130 下 | 55 上 | 130 | |

下巴也成对走，比如 `JL=70 JR=110`，再 `JL=60 JR=120`。

范围是原作者的姿态值，不是针对这台机器量出来的，**不要当成安全值**。

量完改 `firmware/config_mouth.py`。每行是 `名字: (GPIO, a, b, rest)`：

- **a、b 的顺序不要颠倒**。代码里 u=0 对应 a，u=1 对应 b，语义是"上抬 / 张开 / 笑 / 变宽"为 1。
- 只把顶死的那一端往回收，留 5° 余量。
- JL、JR 要保持镜像：JL 改成 55，JR 就改成 125。
- rest 必须落在范围里。

改完要重刷：

```bash
PATH=$PWD/.venv/bin:$PATH firmware/flash.sh mouth
.venv/bin/pytest -q
```

然后慢速扫一遍，确认没有异响：

```bash
.venv/bin/python scripts/servo_check.py --board mouth
```

这个脚本会问每个舵机是否正常。JL 和 JR 自动一起转，结果存在 `outputs/servo_check.json`。

## 5. 表情尝试

先在电脑上看预览，不用接硬件：

```bash
.venv/bin/python scripts/demo_expressions.py --viz     # 输出 outputs/expressions.png
```

再上真机，**从小强度、慢速开始，一个一个来**。只接嘴部板时，其他板的命令会被忽略，开头的提示不用管。

```bash
.venv/bin/python scripts/demo_expressions.py --only neutral --speed 60 --hold 3
.venv/bin/python scripts/demo_expressions.py --only happy --intensity 0.3 --speed 60 --hold 3
```

`--intensity` 按 0.3 → 0.6 → 1.0 加上去。每个强度都确认没有卡住、没有嗡嗡响，再进下一档。全部通过后才跑完整轮播：

```bash
.venv/bin/python scripts/demo_expressions.py --speed 150 --hold 2
```

可选表情：`neutral happy sad angry surprised fear disgust`。

嘴部能看到的变化：

| 表情 | 嘴部动作（满强度） |
|---|---|
| neutral | 全部 rest |
| happy | 嘴角上抬、变宽，下巴微张 |
| sad | 嘴角下撇，略变宽 |
| angry | 嘴角轻微下撇 |
| surprised | 下巴张大（JL 58、JR 122） |
| fear | 嘴角横拉到最宽，下巴微张 |
| disgust | 上唇抬到最高（LUL 40、LUR 140） |

这些数值是手估的，**要对着实物调**。改 `head/expressions.py`，值是 0–1 的 u：

```python
"happy": {
    **_both("CUL", "CUR", 1.0), **_both("CLL", "CLR", 0.7),
    **_both("JL", "JR", 0.2),
```

`_both` 让左右用同一个值。**JL、JR 必须一直用 `_both`。** 眼皮和眉毛的值先不要动，那部分另外调。

调完记录：每个表情拍一张正面照或一段短视频，写下改了什么、哪里还不像。

## 6. 这几件事不要做

- 不要在运行档插拔舵机线。
- 不要单独大幅度转 JL 或 JR。
- 不要接 12V，不要拿 USB 给舵机供电。
- 不要改舵机的名字，也不要改板子上的接法去"统一左右"。JL/JR 的左右和嘴唇相反，这是保留作者命名的决定。
- 不要长时间让舵机顶着或保持高负载。不用时发 `X`，或者断电。
- 不要动 `emo_bench/.env`，也不要提交任何 key。

## 7. 做完交回什么

- 调过的 `head/expressions.py`。
- 表情的照片或视频，以及还不像的地方。
- 遇到的问题：比如 Pico 重启、舵机发热、线被连杆夹住。

代码改动放到新分支 `mouth-tuning`，不要直接推 `main`。
