# 固件协议测试记录（舵机未接 5V）

- 日期：2026-11-06
- 板：mouth（`/dev/serial/by-id/usb-MicroPython_Board_in_FS_mode_e6616407e380b62c-if00` → `/dev/ttyACM1`）
- 固件：共用目录 `firmware/main.py`、`firmware/config_mouth.py`（未改动）
- 条件：只插 USB，舵机 5V 未接；SW1 未拨动；串口独占
- 方法：pyserial 115200 直接发送协议行，用 `G` 读回跟踪角度
- 结束状态：`X` 已发（全部卸力），`V 600` 已恢复，`G` 全部 90.0

## 结论

1. **可以只动一个舵机。** `S JL=80` 只给 JL 通电，JL 从 90 插值到 80，其他舵机保持 90 不动。
2. **同时给多个目标时是并行插值，不是排队一个个动。** `S LUL=100 LUR=80` 在同一个 10 ms tick 里同时更新两个舵机；30°/s 下 0.1 s 各走约 3.3°。
3. `O` 是单舵机测试用的上电命令：只给列出的舵机通电，其余全部卸力。**列出的舵机会瞬间跳到 90°，不走插值。**
4. `R` 和 `C` 会给**全部**舵机通电：`R` 按 `V` 的速度插值到 rest，`C` 瞬间写 90°。量程没确认前不要发。
5. 角度会被 `config_mouth.py` 的 a/b 截断，速度最低 10°/s。

## 代码里发现的问题（未在实机触发，避免把主循环打断）

1. **畸形输入会让固件抛异常退出主循环。**
   - `V` 不带参数 → `IndexError`
   - `V abc`、`S JL=abc`、`S JL`（没有 `=`）→ `ValueError`

   固件没有 `try/except`，异常后 `main()` 退出，串口会掉到 MicroPython REPL，需要复位或重刷才能恢复。建议把 `handle()` 包一层：

   ```python
   try:
       reply = handle(buf)
   except Exception as e:
       reply = "ERR " + repr(e)
   ```

2. **`S` 是边解析边生效。** 前几个名字合法时会先改目标并通电，遇到非法名字才返回错误。要么先全部校验再应用，要么在工具层保证名字合法。
3. **`O` 的 90° 是硬写，不走插值。** 第一次给某个舵机上电时，如果舵盘不在 90°，会全速瞬跳。上电前确认舵盘接近 90°，现场有人守电源。
4. **`V` 没有上限。** 建议加一个合理的最大值，避免误发 `V 999999` 变成瞬跳。
5. **`X` 之后 `G` 仍显示最后角度**，这是跟踪值，不代表舵机还在受力。
