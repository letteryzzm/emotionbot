## 3. 计算逻辑

### 3.1 位置和距离（vision.py）
- MediaPipe 找两眼虹膜中心（landmark 468 / 473）。
- 位置：两眼中点 → 画面归一化坐标 x、y（-1~1，x 右正，y 下正）。
- 距离：针孔模型 `d = f × 0.063m ÷ 瞳距像素`，`f = (w/2) / tan(hfov/2)`，hfov 默认 65°。
- 640 宽时：0.28m ≈ 113px，0.45m ≈ 70px，1.0m ≈ 32px，1.5m ≈ 21px。

### 3.2 眼球跟随（behavior.py）
- 摄像头在两眼中间上方，朝向和机器人一致，画面左 = 机器人左。
- 按实际角度映射：`偏角 = atan(x × tan(hfov/2))`，舵机从 rest 转同样的度数（`增益 = 1` 假设舵机和眼球 1:1，未核对）。65° 视场的画面边缘对应 ±32.5°，不会打到舵机极限。
- 正视回到实测中心：LR 90°，UD 120°（`head/centers.json`，UD=90 时眼睛向下约 30°，15:44 按项目负责人要求写入，方向尚未实测）。每帧 α=0.5 平滑。
- LR 实测范围：90° ± 60°（2026-11-07 项目负责人提供，已写入 `tune_log`）。`config_eyes.py` 限位是 40~140°，生效的是交集 ±50°。调试台实际只转过 LR 60~120°。UD 范围还没记录，调试台实际转过 75~120°，中心以上没试过，而限位 140° 只比中心高 20°。
- 眼球向下看时上眼皮跟着压低（移植自上游 Will Cogley `eyes.py` 的 `control_ud_and_lids`）。
- 丢脸 0.6 秒内眼睛停在原处，之后进入无聊状态，视线每 1.5~4 秒随机游走。

### 3.3 距离 → 表情

| 距离 | 状态 | 表现 |
|---|---|---|
| 无人 或 > 1.5m | bored 无聊 | 眼皮半闭、眉低、嘴角平，眨眼慢而长（0.25s） |
| 0.45 ~ 1.5m | interested 感兴趣 | 眉微抬、眼睁圆、微笑 |
| 0.28 ~ 0.45m | annoyed 不舒服 | 眉内侧压低、眼眯、嘴角微下 |
| < 0.28m | fear 害怕 | 睁大眼、眉上抬、嘴角横拉 |

- 表情每帧向目标姿态靠近 8%（α=0.08），过渡时间和帧率有关。
- **受惊**：人脸移动速度（EMA）> 1.6 画面坐标/秒，叠加 0.6s 惊讶姿态（0.4×当前状态 + 0.8×surprised），冷却 1s，无聊状态下不触发。
- **眨眼**：随机 2~5s 一次，普通 0.12s。
- 姿态向量由 `expressions.py` 的基础表情加 `behavior.py` 里新增的 bored / interested / annoyed 混合得到。

## 4. Web 调试界面

地址：**http://100.93.30.117:8000**（Tailscale 内，或 ROG 本机 `http://localhost:8000`）

功能：
- 实时画面（MJPEG），叠加：绿点=两眼虹膜、连线=瞳距（颜色随距离分区）、`IPD xxpx`、距离数字、黄圈=人脸中心、底部 0~2.5m 距离标尺带分界线和当前位置三角。
- 左上角说明块：当前状态、是否受惊、距离/瞳距、当前表情文字描述。
- 状态读数：距离、人脸位置、移动速度、fps。
- 22 路舵机 u 值实时条。
- 滑条：三个距离分界、视场角 hfov、视线增益、受惊速度阈值、眼球/表情平滑。
- 「强制表情」下拉框、「画面转 180°」勾选框、「发送到真机」开关。
- 全屏：按钮 / 双击画面 / 按 F。

启动与停止（ROG）：

## 6. 本次遇到的问题

1. **「不舒服」状态抛 KeyError**：距离落在 0.28~0.45m 时没有对应姿态。已补姿态，并加了覆盖所有分区的单测。
2. **画质/帧率太卡、摄像头发烫后断流**：降到 640×480、MJPG 取流、限 15fps、JPEG 质量 50、只推新帧、读帧失败 20 次自动重开摄像头。实测仍只有约 8~10fps，ROG 上 Python 只占约 8% CPU，瓶颈疑似摄像头本身（未验证）。
3. **摄像头从系统里消失**（`/dev/video2` 不见，`lsusb` 也没有）：疑似发热掉线或接触不良，重新插拔后恢复。「自动重开」处理不了设备整个断开。建议接带电源的 USB 集线器或换口，`--fps` 降到 10。
4. **pkill 误杀自己所在的 ssh shell**：命令行里包含被匹配的字符串。改用 pid 文件（`run_web.sh`）。
5. 完整 `pytest` 在 ROG 上有 1 个失败：`tests/test_t5_eb2.py::test_sim_without_screen_support_replies_err` 超时，在 Mac 上通过，未查，和本次改动应无关。

## 8. 联调清单（舵机调好后）

1. **走统一控制进程**：`docs/统一控制进程.md` 规定 `head.hub_server` 是唯一持有 Pico 串口的程序。联调用 `camera.hub_source`。`camera.web` 的「发送到真机」开关是在这之前写的，会绕过控制进程直接开串口，也不看标定范围，**联调时不要勾**。首次先确认舵机板供电安全。
2. **眼球方向**：假设 LR 角度增大 = 眼球看向机器人左侧。方向反了时按 `head/actuators.py` 的注释改 `ANGLE_UP_IS_CCW`，`LR_UP_IS_ROBOT_LEFT`、`EYE_BROW_L_IS_ROBOT_LEFT`、`MOUTH_L_IS_ROBOT_LEFT` 都由它推出，所以改它会同时翻转眼皮、眉毛、嘴部的左右，改之前先对照 `docs/舵机接线与上电检查.html`。如果只是摄像头镜像或装反，不要改这个常量。
3. **UD 方向**：同样核对抬头/低头方向，以及眼皮联动是否和眼球协调（上眼皮压低系数 0.4、下眼皮 0.16，是照上游估的，需对着实物调）。
4. **表情幅度**：`behavior.py` 的 `EXTRA` 和 `expressions.py` 里的数值都是按 FACS 直觉估的，要对着实物调，注意不要撞限位。
5. **摄像头和眼球的相对位置**：现在假设摄像头和机器人朝向一致、画面左 = 机器人左。摄像头装在别处（如桌面、头顶）会有视差，大幅偏离时需要加标定映射。
6. **距离标定**：站在 50cm 处用 `camera/track.py --calibrate` 按 `c`，或在页面拖「视场角」滑条，把读数校准到真实距离。
7. **延迟和帧率**：现在 8~10fps，眼球平滑 α=0.5。联调时看舵机是否抖，必要时降 `eye_alpha` 或调固件速度（`HeadClient.speed`）。
8. **安全**：`camera.web` 默认监听 `0.0.0.0` 且没有鉴权，Tailscale 内任何人都能打开并勾「发送到真机」。建议改成 `--host 127.0.0.1` 用 SSH 转发看，和 `hub_server` 一致。

## 9. 已知局限

- 距离是单目估算，**精度没有实测过**，视场角默认值也没校准，读数可能整体偏。
- 侧脸会缩小瞳距，距离被高估；戴口罩或遮挡时检测不稳。
- 受惊只用「脸移动速度」，没有区分晃玩具和人自己动。
- 只做了视觉，语调情绪、表情镜像（`scripts/mimic.py` 已有）和对话情绪标签没接。
