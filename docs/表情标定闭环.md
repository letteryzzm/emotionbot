# 表情标定：调整、保存、重启与标签调用

2026-11-11：现有调试台已支持分组叠加控制、七类表情持久化、加载预览、重放和情绪标签 API。标定台是此流程的唯一串口所有者；识别模块通过 HTTP 调用它。无需 T5。

软件流程已经可运行，真实机器的七类表情仍需要人工调整和确认。历史日志、旧版预设及仿真姿态不会自动成为真机标定。

> 2026-11-11 现场更新：LLR 在 90° 通电时嗡嗡响，已在标定台暂时锁定。先跳过下唇整组，其他组可继续；含 LLR 的旧姿态也会拒绝重放。见 [LLR 异响排查](LLR-90度异响排查-2026-11-11.md)。

> 2026-11-13：用户确认 LLR 舵盘已拆，可用 `--llr-unloaded` 启用专用“90° / 1 秒后卸力”检查按钮。普通 LLR 通电与表情重放仍锁定。仅在空载阶段使用，复装前停止该模式。

## 启动

在项目根目录运行，浏览器访问 `http://127.0.0.1:8770`：

```bash
# 仿真：不打开串口，不修改真实中心配置
.venv/bin/python scripts/tune_server.py --sim

# 真机：先关闭 hub、app.run、tune.py 等其他串口控制程序
.venv/bin/python scripts/tune_server.py
```

真机启动只读取板子的控制角度，不自动通电、不加载动作。点击“加入标定”“重放”或其他动作按钮才发送动作。设备断开后重新接入时会自动卸力。

从 Mac 操作 ROG 上的服务：

```bash
ssh -N -L 8770:127.0.0.1:8770 rog
```

然后在 Mac 打开同一地址。ROG 部署目录是 `/srv/robot-head`。服务只监听本机回环地址，使用 SSH 转发访问。

2026-11-11 已在 ROG 启动 `emotionbot-calibration.service`（用户级临时服务，未设置开机自启）：

```bash
ssh rog 'systemctl --user status emotionbot-calibration.service'
ssh rog 'systemctl --user stop emotionbot-calibration.service'
# 临时服务停止或重启 Linux 后，重新创建：
ssh rog 'systemd-run --user --unit=emotionbot-calibration --property=WorkingDirectory=/srv/robot-head /srv/robot-head/.venv/bin/python /srv/robot-head/scripts/tune_server.py'
```

停止服务会中断任务并向在线板子卸力。也可以直接在 ROG 终端使用前面的 Python 命令运行。

## 标定操作顺序

1. **拼出中性姿态。** 在各电机组点击“加入标定 · 保留其他组”；该组在 Pico 当前控制角度处通电，不卸掉已加入的组。用 ±1° / ±5° 调整。双下巴以整组加入，调整时限制 `JL + JR` 与 180° 的偏差不超过 5°。`EXA` 禁止参与。
2. **保存 neutral。** 选中 neutral，填写名称、说明，点击“保存当前姿态”。保存当前已通电及保持通道的原始控制角度；它们共同定义这套表情的通道集合。可先用少量已检查电机验证流程，再扩展到整脸。
3. **保存其他六类。** 调整为 happy / sad / angry / fear / disgust / surprise，分别保存。每类必须使用与 neutral 完全一致的通道集合；不变化的电机也保存其明确角度。新一类可以先“回到已标定 neutral”再调整。
4. **加载与重放。** 选择标签和 0–1 强度，点击“加载预览”，核对角度后点击“重放预览姿态”。加载不产生任何串口操作。重放按 neutral 到目标姿态插值；默认 1 秒过渡，位移过大时自动延长，不再叠加中心补偿。
5. **重启验证。** 停止服务后用相同路径启动；已保存的标签自动恢复，仍不会自动执行。再次加载并重放，拍照比较实际表情；界面角度来自 Pico 的控制值，不是编码器反馈。

“全部卸力”或 Esc 会中断正在执行的动作。多组已加入时，“本组回中心”只影响该组；“只通这组到 90°”是旧的隔离测试操作，会改变其他组通电状态。旧版预设折叠在独立区域，不参与人工标定库。

保存动作需要等运动结束。修改 neutral 的角度或通道集合，会让旧表情失效；中心或硬件配置改变后也需重新标定。页面显示具体失效原因。保存和重放检查固件配置范围；已有正式实测范围的通道还会检查该范围。尚无实测范围的通道在预览中标出。

## 保存位置与备份

| 内容 | 默认路径 |
|---|---|
| 真机表情库 | `calibration/expressions.json` |
| 仿真表情库 | `outputs/calibration-sim/expressions.json` |
| 真机过程日志与实测范围 | `outputs/tune_log.jsonl` |
| 仿真过程日志 | `outputs/tune_sim.jsonl` |
| 真实中心配置 | `head/centers.json` |

可用 `--library PATH --log-file PATH --port 8771` 指定独立环境；重启要保持相同路径。仿真库带有 `mode: sim`，真机模式拒绝读取，防止误用。

每次保存递增 `revision`，使用临时文件和原子替换，写入失败保留旧库；并检查页面版本及磁盘变更，避免旧副本覆盖新结果。这里的版本号用于一致性检查，历史回退通过 Git 或备份完成。页面“导出表情库 JSON”可下载备份。真机标定完成后，应将此小文件和对应中心配置同步回代码仓库提交；大日志、照片原件继续归档到 T9。

## 从识别结果调用

同一服务提供 `POST /api`，需要 `Content-Type: application/json` 和 `X-Head: 1`。七类标签使用上述英文名，同时兼容旧名称 `surprised` → `surprise`。

```bash
curl -sS http://127.0.0.1:8770/api \
  -H 'Content-Type: application/json' -H 'X-Head: 1' \
  -d '{"op":"emotion","label":"happy","intensity":0.6,"transition":1.0,"hold":2.0}'
```

这条命令会实际通电并执行已保存的 happy，达到目标后保持 2 秒，再以同样过渡回到已标定 neutral。省略 `hold` 或设为 `null` 则保持目标姿态；它不是卸力命令。强度和识别置信度是不同参数，应由上层回应策略决定。

| 参数 / 操作 | 约定 |
|---|---|
| `intensity` | 0–1，默认 1；0 为 neutral |
| `transition` | 0.2–10 秒，默认 1；每 50 ms 指令步长不超过 5°，串口耗时可能使实际过渡更长 |
| `hold` | 0–30 秒或 null；数值表示保持后回 neutral，null 表示保持当前表情 |
| `revision` | 可选；页面重放携带预览版本，过期时拒绝执行 |
| `{"op":"load_expression","label":"happy","intensity":0.6}` | 只预览，结果在 `state.preview` |
| `{"op":"relax"}` | 中断动作并全部卸力 |
| `GET /state` | `busy`、`error`、板子在线情况、表情库状态与控制角度 |
| `GET /expressions.json` | 完整导出 JSON |

成功请求返回 200 与 `state`，动作异步执行；调用方需继续查看 `busy` 和 `error`。未标定、过期配置、动作忙、板子离线、非法参数返回 400 与 `error`，不会退回旧版预设。动作忙时不排队，不打断当前标定；连续识别结果应由上层合并并在空闲时提交最新有效结果。重放时若还有 neutral 集合之外的已知通电通道，会要求先卸力。

目前接通的是“手动标定 → 持久化 → 重放 → 标签 API”。SenseVoice、EmotiEffNet、LoRA 与慢层的实时接入，以及旧 hub / HeadBridge 的迁移，仍按下一阶段方案推进。
