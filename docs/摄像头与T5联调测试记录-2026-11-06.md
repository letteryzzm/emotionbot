# 摄像头与 T5 联调测试记录

- 日期：2026-11-06
- 机器：lettery-ROG-Strix-G16（RTX 4060 Laptop 8GB，Linux）
- 执行：SSH 用户 collab
- 串口占用：仅使用 T5 的 /dev/ttyACM2、/dev/ttyACM3；未触碰 Pico 的 ACM0/ACM1

## 1. 摄像头

### 设备

| 节点 | 型号 | 用途 |
|---|---|---|
| /dev/video0、video1 | Sonix USB2.0 HD UVC WebCam | 笔记本内置 |
| /dev/video2、video3 | Microdia / SHUNCCM USB 2.0 Camera | 外接 |

video1、video3 是 metadata 节点，不能抓图（`VIDIOC_G_INPUT` 报错属正常）。

### 权限

collab 原本不在 video/audio 组，打开设备 `Permission denied`。已在 4060 上执行：

```bash
sudo usermod -aG video,audio collab
```

重新登录 SSH 后确认 `groups` 含 video、audio。这是系统账户改动，不在仓库里。

### 结果

| 设备 | 抓帧 | 分辨率 | 帧率（OpenCV） | 亮度 YAVG | 结论 |
|---|---|---|---|---|---|
| /dev/video0 内置 | 成功 | 1280x720 | 640x480 @ 30.0 fps | ≈102（ffmpeg）/82（cv2） | 正常 |
| /dev/video2 外接 | 成功 | 1280x720 | 640x480 @ 14.3 fps | ≈51 | 能出图但画面很暗，待复测 |

外接摄像头连续曝光 4 秒后亮度没有上升，14fps 也符合低照度下自动曝光拉长曝光时间的表现。判断是镜头被遮挡、贴桌面或未对焦，不是驱动问题。

应用选择摄像头用 `python -m app.run --camera 2`；默认 `--camera 0` 是内置摄像头。

### 应用环境缺口

共享仓库 `.venv` 里没有 `cv2`、`torch`、`emotiefflib`、`sounddevice`，所以应用级 FER 暂时跑不起来。系统 Python 3 有 apt 的 `cv2 4.6.0`，可单独做摄像头验证。需要在演示机上补装视觉/音频依赖后，才能跑完整的 `app.run`。

## 2. T5AI 板

### 枚举

- USB：`1a86:55d2 QinHeng USB Dual_Serial`（CH342）
- `/dev/ttyACM2` → CH342 A（if00）
- `/dev/ttyACM3` → CH342 B（if02）
- 两个口均无其他进程占用（fuser 显示 free）

### 测试

| 项目 | 条件 | 结果 |
|---|---|---|
| 串口读 | 115200 / 460800 / 921600 / 1.5M / 2M | 全部 0 字节 |
| DTR/RTS | 低低、高高、复位脉冲 | 全部 0 字节 |
| UDP 8770 | 监听 12 秒 | 0 包 |
| USB 声卡 | 设备列表 | 没有 T5 音频设备 |

### 结论

板子能枚举出双串口，但完全没有往外发数据。不是波特率问题，最可能是：

1. 固件没有运行或没有烧录；
2. 模块没有上电（CH342 由 USB 供电，模块可能另有开关）；
3. 音频走的是 T5 原生 USB（另一个 USB 口），不是 CH342 的 UART；
4. 固件需要先收到启动命令，或需要先连 Wi-Fi。

### 待队友确认

- 固件是否上电即通过 USB 串口持续推 PCM；
- 波特率、帧格式（帧头/长度/采样率/声道）、启动命令；
- 走 A 口还是 B 口，还是 T5 原生 USB 口；
- 板子电源开关位置和 LED 状态。
