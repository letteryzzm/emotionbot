# 05 后续优化建议

> 按"投入小、收益大"排序。前三条做完验收后就可以马上做；后面的偏研究，可以挑一个变成课题。

---

## 1. 个性化校准（收益最大，成本最低）

**问题**：每个人的"中性脸"和"平常语调"不一样。有人天生嘴角下垂，FER 会一直判成 sad；有人说话本来就快，SER 会判高唤醒。

**做法**：
- 每个用户开始时录 30 秒中性状态，作为 baseline，后续输出减去这个 baseline（FER 的 logits、SER 的 V/A）。
- 进一步：每个用户只训最后一层分类头（几十个样本），用自采数据做 few-shot 适配。

**怎么证明有效**：03 的 C2.4 留一人测试，对比校准前后。

## 2. 置信度校准和"不确定就不说"

**问题**：late fusion 用置信度加权，但神经网络的 softmax 概率通常偏自信，权重就不准。

**做法**：
- 每个模态在验证集上做 temperature scaling，报告 ECE（expected calibration error，预测置信度和实际准确率的差距）。
- 融合后置信度低于阈值时输出"不确定"，机器人做中性表情而不是乱猜。对机器人来说，**猜错情绪比不回应更伤体验**。

## 3. 时间建模

**问题**：逐帧 FER 抖动大，一句话里的情绪也会变化。

**做法**：先用指数滑动平均和 HMM 平滑；再试一个小的时间模型（GRU / 1D conv）跑在 EmotiEffNet 的帧特征序列上，作为 MAE-DFER 的轻量替代。对比 04 的图 2。

## 4. 把大模型蒸馏到小模型

**问题**：Qwen-Omni / LLM 融合效果可能最好，但本地跑不动或太慢。

**做法**：在云上用大模型给大量无标签中文视频（比如 MER 的未标注部分）打软标签，蒸馏到本地的 late fusion 或小融合网络。这也是 MER 挑战赛半监督赛道的主流思路。

## 5. 领域适配到机器人场景

- 用自采数据（机器人摄像头视角、桌面麦克风、舵机噪声）对 SER 和 FER 做少量微调。
- SER 做数据增强：把录下来的舵机噪声、风扇噪声混进训练数据（不同信噪比）。
- 主动学习：demo 运行时把低置信度的片段存下来（经同意），定期人工标注一批再训。

## 6. 多人场景和说话人跟踪

用 FunASR 的 VAD + CAM++ 说话人分离，配合人脸跟踪和嘴部运动检测，把"谁在说话"和"谁的脸"对上。参考 UGotMe（ICRA 2025）的"该关注谁的情绪"。

## 7. 增加模态

- **rPPG**（摄像头测心率，rPPG-Toolbox）：对唤醒度是独立信号，不受表演影响。
- **EEG**：接总报告里的 ErrP 路线。情绪识别结果可以和 ErrP 一起作为机器人表情学习（L4）的奖励信号。

## 8. 端侧部署

- EmotiEffNet、RoBERTa 转 Core ML，用 Apple Neural Engine 跑，降低 CPU / GPU 占用和发热（MacBook Air 无风扇，这一条对长时间运行很重要）。
- LLM 用 MLX 量化；SenseVoice 已有 ONNX / libtorch 版本可以评估。

## 9. 可以发展成课题的方向

| 方向 | 为什么有价值 | 和已有工作的关系 |
|---|---|---|
| **语气和字面矛盾时的多模态识别** | 音频 LLM 的已知弱点（总报告 2.1 提到的 semantic dominance），而机器人对话里很常见 | 03 的 C3 就是这个课题的雏形数据集 |
| **感知 → 表达 → 用户反应 的闭环评估** | 大部分工作只做识别或只做表达 | 用 FER 测"机器人回应之后用户情绪有没有变好"，作为 L4 偏好学习的奖励 |
| **低成本机器人头上的中文情感交互基准** | 公开中文数据都来自影视剧，没有人机对话场景 | 把 C2 的自采集规范化、扩大，可以作为数据集贡献 |

## 10. 伦理和隐私

- 自采数据要签知情同意，说明用途和保存期限；人脸和声音数据只存 `/Volumes/Robotics`，不上传到云端训练（上云只传特征）。
- 机器人"推断出情绪但不该说出来"本身是一个设计问题：默认只用情绪调整表情和语气，不直接说"你看起来很生气"。
