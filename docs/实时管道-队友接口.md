# 实时管道 · 队友接口说明

> 历史接口文档。2026-11-10 已确定后续不使用 T5 开发板，改由电脑直接采集音视频、输出音频，Pico 继续控制电机。下文保留原联调接口，新的模型与输入方案见[下一阶段方案](下一阶段方案-上位机情绪识别与标定.md)。

这份文档只讲**我这边需要你提供什么**，以及**你那边怎么独立验证**。
笔记本端已经按下面的接口实现好了，改协议的话只需要改对应的一个类。

## 1. 拓扑

```
T5AI-Board（麦克风） --UDP PCM--> 笔记本（全部推理 + 决策）
T5AI-Board（扬声器） <--音频----  笔记本（TTS 结果）
USB 摄像头 -------- 笔记本
3 × Pico <---- USB 串口 ---- 笔记本（22 维表情向量）
```

机器人头必须由笔记本驱动；T5 只负责“耳朵”和“嘴”。笔记本上跑 `python -m app.run`。

## 2. 板 → 笔记本：麦克风音频

**推荐协议（已实现，可直接对接）**

| 项 | 值 |
|---|---|
| 传输 | UDP，板子发给笔记本的局域网 IP |
| 端口 | `8770`（可用 `--udp-port` 改） |
| 采样率 | 16000 Hz |
| 声道 | 单声道 |
| 格式 | signed 16-bit little-endian（PCM） |
| 分包 | 每个 UDP 包 20–40 ms（640–1280 字节），长度任意但必须是偶数 |
| 时间戳 | 不需要；接收端按到达顺序拼接 |

**联调步骤（不需要等我的代码完成）**

1. 笔记本上运行接收端：

   ```powershell
   python scripts\t5_echo_server.py --port 8770 --save t5_capture.wav
   ```

2. 板子开始推流，终端会每秒打印一行 `rms=... peak=...`。看到 `rms` 随说话变化就通了。
3. `Ctrl+C` 会把收到的音频存成 `t5_capture.wav`。
4. 把 wav 发给我，我可以直接离线验证识别效果：
   `python -m app.run --source file --wav t5_capture.wav`

**排障**

- 笔记本防火墙要放行 UDP 8770（第一次运行时会弹窗，选“允许专用网络”）。
- 板子如果用 24 kHz 采集，请先在板端重采样到 16 kHz；我不做重采样是有意的——
  SER 模型按 16k 训练，改采样率会直接掉准确率。
- 如果只能走 TCP 或 MQTT，告诉我包格式（是否带长度前缀），我加一个适配器，
  不影响其他部分。

## 3. 笔记本 → 板：扬声器

**这是唯一还没定的接口。** 在我这边确认之前，TTS 输出到笔记本扬声器（逻辑完全一样，
只是声音从笔记本出来）。

两种可选方案，选一个告诉我就行：

**A. HTTP 上传（最简单）**

笔记本 `POST http://<板子IP>:8080/audio`，`Content-Type: audio/wav`，
body 是 16 kHz 单声道 16-bit PCM 的 wav 文件。板子收到后整段播放。

**B. TCP 推流（延迟更低）**

笔记本连到板子 `:8081`，按 20 ms 一包推 16 kHz mono s16le，板子边收边播。
包格式和麦克风方向保持一致（无长度前缀，固定 640 字节）。

A 方案的延迟约等于整句话时长，B 方案首字节就能出声。demo 的回复都很短（≤ 25 字，
约 3–4 秒），A 方案够用；如果板子能轻松实现 B，优先 B。

## 4. Pico 串口

三块板插上后，在笔记本运行：

```powershell
python scripts\list_ports.py
```

输出里能看到每个 COM 口号，以及 `ROLE eyes / brows / mouth` 的应答。
如果自动发现不稳，启动时显式指定：

```powershell
python -m app.run --ports COM5,COM6,COM7
```

不需要改固件；协议保持仓库现有的 `?` / `S` / `G` / `V` / `R` / `C` / `X` 不变。
