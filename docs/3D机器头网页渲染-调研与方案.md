# 3D 机器头网页渲染：调研与方案

2026-11-07。目标：网页上实时渲染机器头，显示舵机参数，动作跟舵机值一致。只显示，不从这里反向控制舵机。

**状态：还没有开始做，这份是给协作者看的方案，需要 collab 确认后再定。**

## 结论

不从零做，也不引入 URDF，直接在 collab 的 `face_gui/` 上接着做。

## 现有基础：`face_gui/`（collab）

- `face_model.html` + `face_model.bundle.js`：three.js + GLTFLoader，加载 `assets/head-clean.glb`（27MB）。
- 截图 `face_gui/rog_desktop.png` 显示 FPS 60。这是页面自己的读数。
- 已有接口：`FaceModel.create(canvas, glb)` 返回的 `setVector(u)`，按舵机名接收 u。
- `head-assembly.blend`（51MB）里零件已经分好并有名字，比如 `LidBR #50`、`眼球 #46`，还有 `04 嘴部 嘴唇连杆` 这样的集合。

读 bundle 代码看到的差距：

| 部位 | 现在的 3D 表现 | 差距 |
|---|---|---|
| 眼球 LR/UD | 只移动贴上去的虹膜小球，眼球模型不转 | 要绕眼球中心转 |
| 眼皮 TL/TR/BL/BR | 四路取平均，上下平移 | 左右不独立；要绕铰链转 |
| 眉毛 LI/LO/RI/RO | 内外取平均，整条平移 | 内外侧不独立 |
| 下颌 JL/JR | 取平均，平移 | 要绕下颌铰链转 |
| 嘴唇 LUL/LUR/LLL/LLR、嘴角 CUL/CUR/CLL/CLR、舌头 TON | `setVector` 里没有处理 | 3D 上不动 |
| 后端 `/api/state`、`/api/expression`、`/api/servo` 等 | 共用目录的 Python 代码里没找到实现 | 目前是预览模式 |

`bundle.js` 是打包产物，共用目录里没看到源文件。改动前要向 collab 要源码。

## 要做的事

1. **接实时数据**：页面改成读真实 u，来源优先用 `head.hub_server` 的合成结果（它才是最终下发值），先确认它有没有可读状态的接口。`camera.web` 的 `/state` 也有 22 路 u，但只含视觉这一路。
2. **平移改成绕铰链转**：给每个运动件加轴心和转轴。这是主要工作量。
3. **补齐舵机通道**：左右眼皮、眉毛内外分开，加上嘴唇、嘴角、舌头。
4. **校方向和行程**：角度范围用 `firmware/config_*.py`，方向和实物核对。用调试台的实测标定（`outputs/tune_log.jsonl`）比用理论值好。

眼皮、嘴唇由连杆驱动，这里只让被驱动的零件绕铰链转，不仿真连杆，视觉上接近，不是真实运动学。

建议顺序：眼球 → 眼皮 → 下颌 → 眉毛 → 嘴部。

## 外部方案（备查，目前不用）

网上没有找到「舵机驱动机器头的网页查看器」这样的现成项目。

| 方案 | 说明 | 为什么不选 |
|---|---|---|
| [urdf-loader](https://gkjohnson.github.io/urdf-loaders/javascript/)（three.js） | 关节 API 完善，`setJointValues` 按名字批量设弧度 | 要重新生成 URDF 和网格；这个头靠连杆，URDF 的串联关节模型帮助有限。可以借鉴它的关节写法 |
| [viewurdf](https://pypi.org/project/viewurdf/) / [scikit-robot 的 Viser 查看器](https://scikit-robot.readthedocs.io/en/latest/reference/viewers.html) | Python 起服务，自带关节滑条 | 同样要 URDF，也不好嵌进现有页面 |
| [TalkingHead](https://unpkg.com/@met4citizen/talkinghead@1.7.0/README.md) | three.js 数字人 | 软件头像，不是舵机结构 |
